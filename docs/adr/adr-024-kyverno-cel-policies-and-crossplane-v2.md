# ADR-024: Kyverno CEL policy types and Crossplane v2 namespaced XRs

**Decision:**
1. Migrate the admission policies from the deprecated `kyverno.io/v1 ClusterPolicy` to Kyverno's CEL policy types (`policies.kyverno.io/v1`): `verify-image-signatures` → **`ImageValidatingPolicy`**, `require-pod-standards` and `disallow-latest-tag` → **`ValidatingPolicy`** (Kyverno chart 3.9 / v1.19).
2. Move the platform S3 API to the **Crossplane v2** model (chart 2.4): a **namespaced composite resource** `ObjectStorageBucket` (`apiextensions.crossplane.io/v2`, `scope: Namespaced`) composing namespaced managed resources (`s3.aws.m.upbound.io`) via a `ClusterProviderConfig`, instead of a cluster-scoped XR + claim.

**Reasoning:**
- `ClusterPolicy` is deprecated since Kyverno 1.17 and scheduled for removal in 1.20; the CEL types reached feature parity in 1.19. Migrating now keeps the next upgrade a no-op. Semantics are preserved 1:1 (`Enforce`→`[Deny]`, `failurePolicy: Fail`, 30s webhook timeout, keyless attestor identity, `mutateDigest`/`verifyDigest`/`required`, prod overlay flips `disallow-latest-tag` from `[Audit]` to `[Deny]`). Tenant scoping uses a `namespaceSelector` on the `platform.io/tenant` label every tenant namespace carries. Kyverno 1.19's cosign verifier auto-detects both the classic `.sig` tag format and cosign v3 sigstore-bundle OCI referrers.
- Crossplane v2 deprecates claims; a namespaced XR gives teams the same UX (`kind: ObjectStorageBucket` in their namespace) with one fewer indirection, and composed resources live in the team namespace, which is easier to reason about for RBAC and cleanup. XR connection secrets are no longer native — `function-patch-and-transform` composes the Secret (same name/keys as before), so consumers are unchanged. The composition now names the bucket `platform-core-prod-<ns>-<name>`, inside the IAM prefix the Crossplane and audio-pipeline IRSA policies are scoped to (previously the generated MR name fell outside it).

**Trade-offs:** The CEL types' storage version is still `v1beta1` in 1.19 (`kyverno migrate` is needed after 1.20). The break-glass runbook commands change object kind (`imagevalidatingpolicy` instead of `clusterpolicy`, `validationActions` instead of `validationFailureAction`). For Crossplane, an existing v1 install must step through 1.20.x first, and because the v2 XRD reuses the claim's CRD name, a live migration needs the buckets orphaned/observed before the old XRD is removed (documented in `docs/crossplane.md`); the AWS path has not run on a live account, so this is documented rather than automated.
