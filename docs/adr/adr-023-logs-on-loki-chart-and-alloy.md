# ADR-023: Logs on the community Loki chart + Grafana Alloy; SeaweedFS replaces MinIO in dev

**Decision:**
1. Replace the deprecated `loki-stack` chart (Loki 2.x + Promtail) with the **`grafana-community/loki`** chart in **Monolithic** (single-binary) mode with filesystem storage in dev, and ship logs with **Grafana Alloy** (`grafana/alloy`, DaemonSet). Tempo moves to the `grafana-community/tempo` chart (Tempo 3.x) for the same reason.
2. Replace the dev-only **MinIO** object store with **SeaweedFS** (`seaweedfs/seaweedfs` chart, all-in-one mode), behind a compatibility `Service minio:9000` in `platform`.

**Reasoning:**
- Promtail reached end-of-life in early 2026 and `loki-stack` is unmaintained; the OSS Loki and Tempo charts moved to `grafana-community/helm-charts` (`grafana/loki` 7.x+ now targets Grafana Enterprise Logs). Alloy is Grafana's supported collector and also speaks OTLP/Prometheus, so it can absorb more collection later.
- Log semantics are preserved: Alloy strips the CRI wrapper, keeps the raw JSON line (the Grafana Loki datasource's `trace_id` derived field still matches it to link Tempo), promotes `level` to a label and attaches `trace_id`/`span_id` as structured metadata (queryable, no label-cardinality blow-up). The Grafana datasource URL (`http://loki.monitoring.svc.cluster.local:3100`, uid `loki`) is unchanged.
- MinIO community edition no longer publishes images/charts reliably, which makes it a fragile bootstrap dependency. SeaweedFS is Apache-2.0, has an actively published chart, and its S3 gateway accepts static admin credentials from `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, so the existing bootstrap `minio-credentials` Secret (`rootUser`/`rootPassword`) is consumed unchanged. The S3 gateway listens on **9000** so the services' NetworkPolicy egress rule (platform ns, TCP 9000) and `S3_ENDPOINT_URL` keep working with zero service changes. The `audio-pipeline` bucket is created by the chart's idempotent bucket hook Job.

**Trade-offs:** Monolithic Loki on local disk is not durable or HA — fine for dev; prod would need S3 object storage (Crossplane bucket + IRSA) and Distributed/SimpleScalable mode. Alloy needs a read-only hostPath to `/var/log` (as Promtail did). The `minio` Service name is now a misnomer kept purely as a contract; renaming it means touching every service's dev overlay and NetworkPolicy, deferred deliberately. SeaweedFS's S3 compatibility is narrower than MinIO's at the edges (e.g. some bucket-policy/ACL features) — the pipeline only uses basic object put/get/list with path-style addressing, which was verified against the image.
