# DEV acceptance report — 2026-11-09

The fresh local environment demonstrated working GitOps delivery, portal service
generation, authenticated audio processing, telemetry correlation, tenant
boundaries, and recovery from a failed canary. This report records working-tree
results, including defects found and retested. Core dev acceptance checks passed
after correction; the known telemetry gaps and transient HTTP failures below
remain explicit limitations.

## Environment and method

The existing `kind-platform-core` cluster used Kubernetes 1.30 and kindnet,
while the repository targets Kubernetes 1.36 and Cilium. It also contained
failed upgrades and degraded Applications. Its three node containers were
stopped to free Docker capacity; they and their data were preserved. It was
not repaired, deleted, or used as the acceptance baseline.

A separate ARM64 `kind-platform-core-qa` cluster used Kubernetes **1.36.4**,
Cilium **1.20.4**, three nodes, and a Docker allocation of **16 GiB**. Alternate host ports
18000/18443 avoided the original cluster's ports. Seven service images were
built and loaded with the QA tag. Commands selected the QA context explicitly.

Unpublished source was copied into a local Git snapshot and served to Argo CD:
raw files on port 19418, Git smart HTTP on 19419. Plain Git HTTP worked with the
Git CLI but not Argo CD's Git implementation, so the smart adapter was needed.
Snapshot `4a27f229d4b05ba46b955f28c84a8c5e9f57c802` was used for the initial
observability checks; `b86c0cad68593de5cbb4f2efb742a14fefc9ef60` includes
the Tempo memory correction and process-ownership fix used for the final retests.
Snapshot `1ac611c40352cfc1e1ad646a06bf886f771f7fa1` additionally fixes Alloy
coverage on tainted nodes; Tempo was not restarted for that change.
URLs with and without `.git` both needed rewriting to avoid accidentally
reconciling published tenant manifests. No external repository was published.

Checks used HTTP/API calls, Kubernetes inspection, server-side dry runs, actual
message/object/state inspection, and controlled test workloads. No browser
visual inspection was performed. No credential values or user audio are
included; the audio input was a synthetic one-second mono 16 kHz WAV.

## Defects found and retested

| Defect | Correction and retest |
|---|---|
| Bootstrap could reuse incompatible existing nodes/CNI | Explicit rejection of non-1.36 nodes and kindnet reuse; named cluster/config options support a fresh environment. An updated image pin alone does not upgrade an existing cluster. |
| Rollouts plugin init container could not satisfy numeric non-root requirements/write its shared volume | Numeric UID/GID and shared-volume group added; architecture-specific plugin checksums verified. Controller started and the live canary ran. |
| ApplicationSet removed the canary's temporary reconciliation pause | Preserve the skip-reconcile annotation, then restore its original state. First attempt stopped on unexpected reconciliation; final bad-canary run passed. |
| Canary fixture preparation falsely rejected the actual echo handler | Anchor the source guard to its full line so the nested exception handler cannot match it; rebuilt both images, then verified the runnable fault in the live exercise. Regression tests preserve health/readiness/metrics functions. |
| Canary port-forward collision | Retest exposed occupied port 18081; allocate a free port by default and establish forwarding before any mutation. Final bad-canary run passed. Earlier failed attempts remain evidence, not successful recovery claims. |
| Background port-forward survived its script | Launch kubectl directly so cleanup tracks its actual PID, instead of a shell-function wrapper. Reproduced the old leak in an isolated test; success and failure paths now assert process exit. The identified orphan was stopped. A further live bad-canary run passed in 103 seconds, exited 0 after restoration, and left no forwarding process. |
| Prometheus Operator 0.95.1 image indexes lacked ARM64 | Hold the entire chart at 92.20.0 with matching 0.94.2 controller/reloader/CRDs; verified both architectures in registry indexes and successful fresh-cluster startup. No old-cluster CRD downgrade attempted. |
| Custom PrometheusRules were never reconciled | Register `observability/prometheus` through `monitoring-rules`; all 14 alerts and 14 recording rules validated and evaluated live. |
| SLO dashboard referenced nonexistent recording series | Use implemented `slo:*` names and explicit window queries; live corrected panels returned samples. The budget panel identifies available-history limits. |
| GitOps dashboard lacked metrics and miscounted combined failures | Enable controller metrics and add a GitOps ServiceMonitor; count the union of degraded/out-of-sync Applications before aggregation. Inventory/state queries now populate. |
| Alloy concatenated both application labels | Prefer `app.kubernetes.io/name`, fallback to `app`; pinned runtime validation passed and fresh Loki evidence has the correct label. |
| Alloy missed the tainted control-plane node | Add a NoSchedule toleration for node-level log collection, covering kind's Envoy node and tainted worker nodes. The two-pod DaemonSet previously left Envoy logs absent from Loki. Retested at three ready pods and correlated a fresh Gateway request with its centralized Envoy log. |
| Tempo OOM during sustained canary traffic | Observed exit 137 at the old 512 MiB limit, with a sampled 508 MiB working set. Raise request/limit to 512 MiB/1 GiB and set the verified runtime Go soft budget to 800 MiB. Two consecutive load runs then passed without a restart on the same pod, beyond the earlier failure timing window. |
| Tenant RBAC still granted legacy Ingress access | Replace it with HTTPRoute permissions; all 13 authorization assertions passed without granting Gateway/ReferenceGrant or guardrail mutation. |
| Backstage guest sign-in returned 403 in the packaged production Node runtime | Explicit opt-in only for dev, selected by ApplicationSet; prod/default guest disabled and invalid prod settings rejected. Live dev authentication passed. |
| Portal implied unsupported frontend integrations and queried absent metrics API | Disable unsupported default integration flags; correct workload selectors; skip pod metrics when metrics-server is absent, with optional read-only RBAC when enabled. Final Kubernetes API check passed. |
| Portal configuration updates did not force rollout | Add configuration checksum and existing-Secret credential references; chart/scaffolding suite passes 13 tests. No credential embedded or disclosed. |

The old Loki installation had an immutable StatefulSet selector mismatch and no
Service endpoints after an upgrade. Fresh installation passed; migration of that
old data remains a separate, unperformed procedure. A temporary QA raw-HTTP
Backstage tree fetch returned 500 because its reader lacks `readTree`; uploaded
directory dry-run verified the unpublished source. Published GitHub tree reading
was not exercised.

A heavy diagnostic boto3 process inside the 256 MiB audio API pod coincided with
one OOMKilled restart before acceptance. The API recovered and completed the
job without another restart. Subsequent evidence collection used a separate
512 MiB diagnostic pod, which was removed. This is an instrumentation limitation,
not a production sizing or resilience guarantee.

Tempo replacement deliberately reset its local `emptyDir` trace storage. After
replacement, a fresh audio trace `c23fe12258eaf3a7b8139e48c9127547` was retrieved
across all five services; earlier trace responses remain saved as evidence.
This does not demonstrate durable trace retention across pod replacement.

## Known boundaries

Six kind scrape endpoints remain unavailable: controller-manager:10257,
scheduler:10259, etcd:2381, and kube-proxy:10249 on all three nodes. They refuse
connections; application scraping and tenant policy checks passed. The final
snapshot had **34 of 40** targets up, with these six as the only failures.
No claim is made that all targets are healthy. Production monitoring
configuration was not changed to hide these local limitations.

The six load-test failures were HTTP 503 with Envoy flag `UC` and
`upstream_reset_before_response_started{connection_termination}`. Echo recorded
no corresponding application errors or restarts. The first two connections
had been idle about 5.1 seconds, consistent with a race against Uvicorn's
five-second keepalive timeout; that underlying cause is an inference, not a
proven socket-level diagnosis. Both load runs met the configured error/latency
thresholds. They were not zero-error runs, and no retry-policy change was made.

Kafka Exporter is disabled in dev; exporter-based lag/DLQ panels are empty.
Real vLLM/GPU panels are also absent. STT/TTS are stubs and LLM uses vllm-mock
through the authenticated gateway. Local Prometheus retains six hours, so no
30-day SLO, real ML quality/performance, AWS operation, or cost savings are proven.
Backstage GitHub publishing, promotion PRs, registry signing/admission, production
identity/database setup, and visual browser interactions remain untested.

The Tempo test covered over 15 minutes of one pod's lifetime, including two
seven-minute load profiles without a reset between them. It does not establish
a long-term memory plateau or production capacity.
